# v0.1 验证记录

日期：2026-10-02。环境：Windows、Node.js 22.23.2、pnpm 10.18.0、Harness 0.2.0-rc.2、Cordis 4.0.4。

## 已验证

- `pnpm check`：TypeScript 检查、26 项测试及 Host/Client 构建通过。
- 本机真实 WebSocket mock 上游：run-task、等待 task-started、二进制音频顺序、finish-task、句尾结果及 task-finished。
- 客户端异步权限申请取消、连接等待缓冲、残余音频先于结束指令、断线取消及 120 秒上限正常收尾。
- 快捷键长按/点按状态机、重复事件、左右 Alt 区分、AltGr 排除、按住期间改变模式。
- 草稿追加、引用芯片坐标、自动发送动作顺序、编辑后抑制自动发送、锁定时保留结果。
- 用 `dsh plugin --profile web add F:/dsh-speeker` 安装到独立测试 profile 并启动，Client 模块能实际激活。
- 实际 Harness 设置页：默认模型、右 Alt、长按、自动发送关闭；API Key 保存成功且不回传密钥；刷新页面后配置仍可用。
- 实际 Chromium 页面：合成麦克风音频通过真实 AudioWorklet 产生 242 个 PCM 块（774400 字节）；麦克风录音按钮显示绿色，停止时释放轨道。
- 浏览器 mock 最终结果将 `已有草稿。` 更新为 `已有草稿。这是流式语音测试。`，没有自动发送。
- 实际 Host 设置接口：无登录状态返回 401，外部 Origin 返回 403。
- `pnpm verify:package`：安装包包含 9 个必需文件，包含客户端模块工厂、PCM worklet 和本验证记录，排除了凭据、测试 profile、node_modules 等私有文件。

## 人工云端验收

1. 按 README 安装，在设置页填写真实百炼密钥、对应地域和 Workspace ID。
2. 先确认自动发送关闭。用麦克风按钮和右 Alt 各录一次，检查开头、句尾和停止后的等待时间。
3. 点按模式中检查第二次按下停止、松开不重启。
4. 草稿中已有文字和引用时录音；等待期间继续编辑，确认文字和引用完整、一次撤销能撤回追加。
5. 开启自动发送，用没有敏感内容的草稿检查完整提交；录音期间编辑草稿，确认只追加并提示手动发送。
6. 录音期间切出窗口、切换会话、按 Escape，检查浏览器麦克风标记消失、迟到结果不写入其他会话。
7. 在 AltGr 布局输入特殊字符，确认不触发录音；改绑 F8 再检查正常录音。
8. 分别使用错误密钥、不可用模型和断网状态，检查明确错误、无自动重试、无自动发送。
